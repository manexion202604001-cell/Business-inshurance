## 0. あなた（Claude Code）への指示

### 0.1 役割
あなたはシニアのフルスタックエンジニア兼プロダクトエンジニアです。法人保険（経営者保険）の営業現場で、**商談の休憩中などのスキマ時間（目安5分以内）に、根拠付きの3パターン提案資料を出せる**Webアプリを作ります。

### 0.2 進め方のルール
- §12 のフェーズ順に進める。**各フェーズの完了条件を満たしたら作業を止め、成果・未解決事項・次フェーズの計画を報告**してから次に進む。
- 仕様が曖昧な箇所は、合理的な仮定を置いて進め、`docs/DECISIONS.md` に「仮定・理由・変更容易性」を1行ずつ記録する。**止まって質問するのは、税務・コンプライアンス上の判断が分かれる場合だけ**。
- **数値計算はすべてコードで行い、LLMに計算させない。** LLMの役割は「抽出・構造化・言語化」に限定する（§3 原則1）。
- 各フェーズで `pnpm lint && pnpm typecheck && pnpm test` がすべて通る状態でコミットする。
- 日本語のUI・出力。コード識別子・コメントは英語でよい。

## 1. プロダクト概要

### 1.1 目的
- 提案根拠の言語化が苦手な営業担当者の商談を支援する
- 商談ログ＋企業情報から **「その場で3パターンの提案資料」** を自動出力し、即時提案・クロージングにつなげる

### 1.2 利用者と利用シーン
| 利用者 | シーン | 必要なもの |
|---|---|---|
| 営業担当者（主） | 商談の休憩中・移動中にスマホ/タブレットで操作 | 最短操作で3案、顧客提示用ワンペーパー、話す順番が分かるトークスクリプト |
| 営業マネージャー | 提案内容の確認・承認、ナレッジ更新 | 承認フロー、生成履歴、監査ログ |
| 管理者 | 保険種別・ロジック辞書・テンプレート・マスキング辞書の保守 | 管理画面（CRUD）、基準日管理 |

### 1.3 成功指標（Phase 4 で計測）
- 入力完了 →3案＋資料出力まで **P50 60秒以内 / P95 120秒以内**
- 生成物のコンプライアンス違反（社名・商品名の露出、禁止表現）**0件**（自動チェック＋人手レビュー）
- 数値の不整合（計算結果と文章中の数値の不一致）**0件**
- 営業担当者の評価「そのまま顧客に見せられる」割合 70%以上

## 2. スコープ

### 2.1 対象（MVP）
- 契約形態：**契約者＝法人／被保険者＝役員（主に代表者）／受取人＝法人** を中心に設計
- 保障目的：①事業保障資金 ②死亡退職金・弔慰金 ③勇退退職金（生存退職金）準備 ④就業不能・三大疾病への備え ⑤従業員の福利厚生（退職金準備）
- 出力：3案比較、顧客提示用ワンペーパー（サマリー型／設計書型）、営業向けトークスクリプト・根拠解説メモ

### 2.2 対象外（MVPではやらない）
- 正式な保険料見積り・設計書の発行（保険会社の設計システムの役割。本システムは「提案骨子と概算」まで）
- 申込手続き・告知・契約管理
- 特定商品の推奨・他社商品との比較表示（§3 原則3）

## 3. 設計原則（最重要・すべてのフェーズで守る）

1. **計算はコード、言語化はLLM**
   必要保障額・税務区分・退職所得・インフレ換算・不足額はすべて `packages/engine` の純関数で計算し、ユニットテストで固定する。LLMにはその計算結果（JSON）を渡し、文章化だけをさせる。
2. **数値グラウンディング**
   LLMが出力した文章中の数値は、すべて計算結果セット（`CalcResult`）に存在する値でなければならない。後段の検証器で文中の数値を抽出して照合し、**存在しない数値があれば再生成（最大2回）→ それでも駄目なら該当箇所を定型文に差し替え**る。
3. **コンプライアンスは fail-closed**
   - 顧客提示物には **保険会社名・商品名・特別勘定（ファンド）名・資料番号（Form No. 等）・募集代理店名を一切出さない**。「変額保険（定期型）Aプラン」のようにカテゴリ＋記号で表示する。
   - 他社・他商品との優劣比較表示をしない（保険業法300条1項の誤認防止の趣旨）。3案は**同一顧客に対する保障設計の選択肢**として提示し、商品比較にはしない。
   - **「節税」を訴求しない。** 法人保険は「保障」を目的とする商品であり、支払保険料を損金算入しても保険金・解約返戻金は益金算入され、通期での節税効果はない旨を必ず注記する（参考資料すべてに同旨の記載あり）。
   - マスキング・禁止表現チェックに1件でも引っかかった資料は**出力（PDF化・表示）をブロック**し、該当箇所を示す。
4. **出典と基準日を必ず持つ**
   ナレッジの各レコード（税務ルール、統計値、功績倍率、返戻率サンプル等）は `source`（資料名・ページ）と `asOf`（基準日）を持つ。資料には「◯年◯月現在の税制にもとづく一般的な取扱い」を自動で記載する。
5. **「イメージ・概算」であることを明示**
   保険料・返戻率は参考値。全出力に「正式な保険料・解約返戻金は保険会社の設計書でご確認ください」「個別の税務は税理士・所轄税務署にご確認ください」を入れる。
6. **書体は明朝体**
   顧客提示資料・PDFの本文と見出しは明朝体（Noto Serif JP をローカル同梱）。UIはゴシックでよい。

## 7. ナレッジベース（seed データ）

`packages/knowledge/seed/*.json` に以下を作り、`prisma db seed` で投入する。**すべて管理画面から編集可能**にし、編集は `KnowledgeVersion` で版管理する（生成時の版を `Case.knowledgeVersion` に記録）。

### 7.1 保険種別マスタ（カテゴリ）

顧客提示ではこの `name`（＋A/B等の記号）だけを使う。

| code | name | 主な用途 | メリット | デメリット・注意 | 税務参照 |
|---|---|---|---|---|---|
| `TERM_LOW_CV` | 定期保険（低解約返戻金型） | 事業保障（借入金返済・運転資金） | 保険料が割安／保障額を大きく確保しやすい | 解約返戻金がほぼない→退職金財源にならない | 返戻率区分で判定（多くは50%以下） |
| `TERM_LEVEL_LONG` | 長期平準定期保険 | 事業保障＋勇退退職金の財源 | 保障と解約返戻金の両立、返戻率ピークを勇退時期に合わせやすい | 保険料が高め／早期解約は返戻率が低い／資産計上が生じやすい | 返戻率区分で判定 |
| `TERM_DECREASING` | 逓減定期保険・収入保障型 | 借入金残高に合わせた事業保障 | 借入残高の減少に合わせ保障が減るため保険料効率が高い | 後年の保障が小さい／返戻金はほぼない | 返戻率区分で判定 |
| `VARIABLE_TERM` | 変額保険（定期型） | 事業保障＋退職金財源（運用で上振れ余地） | 死亡保険金は基本保険金額が最低保証／定額保険より保障を合理的に確保しやすい／解約返戻金を退職金・事業資金に活用可／契約者貸付あり | **投資リスクは契約者に帰属・解約返戻金に最低保証なし**／諸費用あり／一定期間内（5年未満・10年未満など保険会社により異なる）の解約・減額は解約控除／**変額保険販売資格が必要** | 予定利率で推移した場合の最高返戻率で判定 |
| `WHOLE_LIFE` | 終身保険 | 相続・事業承継、退職金原資の長期準備 | 保障が一生涯／解約返戻金が積み上がる | 保険料が高い／保険料は原則資産計上 | 原則資産計上 |
| `THIRD_SECTOR` | 医療・がん・三大疾病・就業不能保障 | 経営者の就業不能リスク | 死亡以外（長期療養・就業不能）の経営リスクに備えられる | 保障範囲・支払要件に制限／告知が必要 | 返戻率区分で判定（無解約返戻金型は多くが全損） |
| `ENDOWMENT_HALF` | 養老保険（福利厚生プラン） | 従業員の退職金準備・福利厚生 | 要件を満たせば保険料の1/2損金／従業員の定着 | **原則全従業員加入などの普遍的加入要件**／役員のみの加入は不可 | 1/2資産計上・1/2損金（要件あり） |

各カテゴリに `mandatoryDisclaimers`（必須注記）を持たせる。例：`VARIABLE_TERM` →「特別勘定の運用実績により損失が生じるおそれがあります」「解約返戻金額に最低保証はありません」「お客さまにご負担いただく費用があります」「一定期間内の解約等には解約控除がかかります」。

**参考資料から得た変額保険（定期型）の典型的な特長（保険会社名は付けずに `variants` として保存）**
- バリエーションA：保険期間を勇退までに設定し死亡保障を合理的に確保／死亡保険金は最低保証／高度障害保険金なし／満期保険金なし（満了時に積立金があれば積立金を支払）／10年未満の解約・減額・払済変更で解約控除
- バリエーションB：契約年齢15〜75歳、70〜100歳満了（1歳刻み）、基本保険金額100万〜5億円／死亡・高度障害保険金は最低保証／特別勘定は9種から選択・スイッチング年12回無料／三大疾病での保険料払込免除特約（付加時は基本保険金額3,000万円まで）／簡易告知あり／終身保険などへの無告知変換可／5年未満の解約等で解約控除

### 7.2 税務区分ルール（法人税基本通達9-3-5・9-3-5の2）

契約形態：契約者＝法人、被保険者＝役員・従業員、受取人＝法人。保険期間3年以上の定期保険・第三分野保険。全期払（保険期間＝払込期間）を前提とする。短期払は Phase 2 以降で対応（`docs/DECISIONS.md` に記録）。

| 区分 | 最高解約返戻率 | 資産計上期間 | 資産計上額 | 取崩期間 |
|---|---|---|---|---|
| 1 | 50%以下 | なし | ―（全額損金） | ― |
| 2 | 50%超〜70%以下 | 保険期間の当初40% | 当期分支払保険料 × 4/10（6/10損金） | 保険期間の75%経過後〜満了、資産計上累計を均等に取崩し |
| 3 | 70%超〜85%以下 | 保険期間の当初40% | 当期分支払保険料 × 6/10（4/10損金） | 同上 |
| 4 | 85%超 | 原則：契約日〜解約返戻金相当額が最高となる期間まで（※） | 1〜10年目：保険料×最高返戻率×**9/10**、11年目以降：保険料×最高返戻率×**7/10**（当期分支払保険料が上限） | 解約返戻金相当額が最高となる期間の経過後〜満了、均等に取崩し |

- 例外：区分2で **1被保険者あたりの年換算保険料相当額（他社契約も合算）が30万円以下** の場合は全額損金
- ※区分4の資産計上期間の延長：最高返戻率期間経過後に「(当年度の解約返戻金相当額−前年度の解約返戻金相当額) ÷ 年換算保険料相当額 > 7/10」となる期間があればその期間まで。上記期間が5年未満なら5年（保険期間10年未満なら保険期間の50%）まで
- 年換算保険料相当額 ＝ 保険料総額 ÷ 保険期間（年）。終身の第三分野は116歳到達までを保険期間とみなす
- 変額保険は **契約時の予定利率で推移した場合の最高解約返戻率** で判定
- 仕訳例（検証用・§13のテストに入れる）：契約年齢50歳、保険期間40年、年払100万円
  - 区分2：資産計上期間16年：前払保険料40万／支払保険料60万 → 資産計上累計640万 → 取崩期間10年：支払保険料164万（うち取崩64万）
  - 区分3：資産計上期間16年：前払保険料60万／支払保険料40万 → 累計960万 → 取崩期間10年：支払保険料196万（うち取崩96万）
- 出力注記（必須）：「支払保険料を損金算入しても、保険金や解約返戻金等は益金に算入され、通期での節税効果はありません」「記載の税務取扱は◯年◯月現在の税制にもとづく一般的な取扱いです。個別の取扱いは税理士・所轄税務署にご確認ください」

### 7.3 必要保障額ロジック（`packages/engine/coverage.ts`）

**2方式を両方計算し、画面で並べて見せる**（既定の採用方式はロジック辞書の設定で切替。初期値は「運転資金方式」）。単位はすべて万円、端数は四捨五入。

**方式A：積上げ方式（出典：経営者のリスク）**
```
事業保障資金 = ①借入金相当額 + ②経営立て直し資金 + ③納税準備資金
  ① 借入金相当額 = 金融機関借入金＋買掛金など（＋経営者からの借入金）
  ② 経営立て直し資金 = 次のいずれか
       A: 経営者死亡後の売上予測と業種別データから、以後3年間の損失（赤字）を試算
       B: 従業員給与（月間人件費）× N か月（既定 N=6、設定可）
  ③ 納税準備資金 = (① + ②) ÷ (1 − 実効税率) × 実効税率    ※実効税率の既定 33.58%（設定可）
```

**方式B：運転資金方式（出典：ソニー生命・チューリッヒ生命資料の例示）**
```
事業保障資金 = 当面の運転資金 + 借入金・負債の返済資金 + 一括返済が必要な借入金・営業債務
  当面の運転資金 = (月間人件費 + 月間その他固定費) × 経営が落ち着くまでの月数（既定12、目安6〜12）
  返済資金      = 月々の借入返済額 × 同月数
  資料の例：(500+200)×12 + 50×12 + 3,000 = 1億2,000万円
```
注記：「借入金および負債の返済資金を生命保険で準備する場合は、法人税等の負担を加味して保障額を検討する必要があります」

**死亡退職金・弔慰金**
```
死亡退職金 = 最終報酬月額 × 役員在任年数 × 功績倍率
弔慰金     = 最終報酬月額 × 36か月（業務上の死亡） / × 6か月（業務外の死亡）   ※既定は業務外（保守的）
遺族側の非課税枠：死亡退職金 500万円 × 法定相続人数（相続税法12条1項6号）
                  弔慰金は上記月数の範囲内で非課税、超過分は死亡退職金とみなす（相基通3-20）
例：190万 × 12年 × 2.4倍 = 5,472万円
```

**必要保障額と不足額**
```
必要保障額 = 事業保障資金（採用方式） + 死亡退職金 + 弔慰金
不足額     = max(0, 必要保障額 − 既存保険の死亡保障合計（被保険者ごと）)
```

**勇退退職金（生存退職金）**
```
勇退退職金 = 報酬月額 × (在任年数 + 勇退までの年数) × 功績倍率
インフレ調整後 = 勇退退職金 × (1 + 物価上昇率)^勇退までの年数     ※既定 2.0%
例：3,600万円、2.0%、20年 → 約5,349万円（差額 約1,749万円）
```

**退職所得（個人側の手取り比較・根拠文用）**
```
退職所得控除 = 勤続20年以下：40万 × 勤続年数（最低80万）
             勤続20年超：800万 + 70万 × (勤続年数 − 20)
課税退職所得 = (退職金 − 退職所得控除) × 1/2      ※分離課税
  例外：役員等勤続年数5年以下の「特定役員退職手当等」は1/2を適用しない
所得税＋住民税の概算は速算表（管理画面で編集可、基準日付き）で計算し、
「役員報酬に上乗せした場合」と「役員退職金で受け取った場合」の差額を示す
```

**功績倍率（役位別の例、出典：エフピー教育出版「令和7年企業経営と生命保険に関する調査」）**
会長 2.3／社長 3.0／専務 2.0／常務 1.8／取締役 1.7（社長の一般的な目安は2〜3倍、最高3倍程度。設定可）

### 7.4 ロジック辞書（経営状況 → 適したプラン構成）

`LogicRule` は「条件（JSON Logic 形式）→ 推奨カテゴリ・加点・根拠テンプレID」。エンジンは全ルールを評価してカテゴリごとのスコアを出し、§8 Step4 で3案に割り付ける。初期ルール例（管理画面で追加・調整できること）：

| ID | 条件 | 推奨 | 根拠の骨子 |
|---|---|---|---|
| R01 | 借入金 ÷ 年商 ≥ 0.3 または 代表者が連帯保証あり | `TERM_DECREASING` `TERM_LOW_CV` 加点 | 借入金の返済と連帯保証債務の相続リスクに、残高に合わせた保障で備える |
| R02 | 不足額 > 0 かつ 経常利益が小さい（年商の3%未満）| 最小プランの保険料上限を下げる、`TERM_LOW_CV` 加点 | 資金繰りを圧迫しない範囲で最大の保障を先に確保する |
| R03 | 勇退まで10年以上 かつ 退職金準備が未整備 | `TERM_LEVEL_LONG` `VARIABLE_TERM` 加点 | 返戻率のピークを勇退時期に合わせ、退職金の財源とする |
| R04 | 代表者年齢 ≥ 60 | `THIRD_SECTOR` 加点、長期の変額は減点 | 経営者の高齢化で就業不能リスクが高まる（経営者年齢の山は23年で47歳→69歳、男性の健康寿命72.68歳：いずれも資料の統計、基準日付き） |
| R05 | 従業員数 ≥ 10 かつ 従業員退職金の準備が未整備 | 最大プランに `ENDOWMENT_HALF` を追加 | 従業員の生存退職金は「いつかは必ず発生する」負債 |
| R06 | 事業承継・相続の話題が商談ログにある | `WHOLE_LIFE` 加点 | 納税資金・遺産分割資金の準備 |
| R07 | 純資産が小さい／赤字決算の話題 | 資産計上の大きい区分（区分3・4）を減点 | 赤字決算は信用低下→融資困難→倒産に至るリスクがある |
| R08 | 既存保険の返戻率ピークが勇退時期と大きくずれている | 「見直し」論点を根拠メモに追加 | 既存契約の活かし方を先に整理する |

**保険料予算の目安**（ヒューリスティック。事実ではないため設定値として管理し、画面に「目安」と明記）
最小＝経常利益の5%／バランス＝10%／最大活用＝20%（いずれも上限。経常利益未入力なら年商×0.5%を仮置きし、その旨を表示）

### 8.2 Step3〜4 の出力 `CalcResult` / `PlanSet`（型の要点）
```ts
type Money = { value: number; unit: '万円'; calcId: string; formula: string; inputs: Record<string, number>; source?: string };
type CalcResult = {
  coverage: { methodA: Money; methodB: Money; adopted: 'A'|'B'; deathRetirement: Money; condolence: Money; required: Money; existing: Money; gap: Money };
  retirement: { target: Money; inflationAdjusted: Money; deduction: Money; taxable: Money; netVsSalary?: Money };

  assumptions: string[];   // 仮置きした値の説明

};
type Plan = {
  tier: 'MIN'|'BALANCED'|'MAX';
  title: string;           // 例：「まずは借入金を守る」最小プラン
  components: { categoryCode: string; label: string /* 例:定期保険（低解約返戻金型）Aプラン */; deathBenefit: Money; termToAge: number; purpose: string;
                premiumEstimate?: { low: Money; high: Money } | 'DESIGN_SHEET_REQUIRED'; taxBucket?: 1|2|3|4; peakYear?: number }[];

  ruleHits: string[];      // 適用したロジック辞書ID

```
**3案の割付方針（初期値）**
- **最小プラン（着手しやすい）**：不足額のうち「借入金相当額（または一括返済分＋当面の運転資金）」を最優先で、保険料が最小になるカテゴリで確保。予算上限＝最小
- **バランス型プラン**：不足額の全額＋勇退退職金目標の一部（返戻率ピークを勇退時期に合わせる）。予算上限＝バランス
- **最大活用型プラン**：必要保障額の全額＋勇退退職金目標（インフレ調整後）＋R04/R05該当時の第三分野・福利厚生プラン。予算上限＝最大
- 予算上限を超える場合は保障額を段階的に下げ、下げた旨と充足率を表示する

## 9. プロンプト設計（`packages/llm/prompts/`）

共通 system（キャッシュ対象）の骨子：
```
あなたは法人保険の提案資料を作成する、中立的なファイナンシャル・アナリストです。
- 目的は「経営者に万一のことがあった場合でも会社が存続できる資金の準備」と「役員退職金の財源準備」を、第三者の視点で論理的に説明することです。
- 数値は与えられた CALC_RESULT の値だけを使い、新たに計算・推測しないでください。各根拠文には参照した calcId を付けてください。
- 保険会社名・商品名・ファンド名は出力しないでください。カテゴリ名とラベル（例：変額保険（定期型）Aプラン）だけを使ってください。
- 節税を目的・効果として訴求しないでください。税務は「経理処理の取扱い」として事実のみ述べ、通期での節税効果はない旨の注記を残してください。
- 「必ず」「確実」「元本保証」「他社より有利」などの断定・保証・比較表現は使わないでください。
- 根拠は「事実（この会社の数値）→ 基準（一般的な算式・統計と出典）→ 算定結果 → だから必要」の順で書いてください。
- 営業担当者が話しやすい、平易で丁寧な日本語にしてください。
<KNOWLEDGE>（保険種別マスタ、ロジック辞書の根拠テンプレ、統計値、禁止表現、必須注記）</KNOWLEDGE>
```
- Step2（抽出）と Step5（言語化）はそれぞれ専用の user プロンプト＋ tool 定義。温度は Step2=0、Step5=0.4。
- **Few-shot**：Phase 1 で作る「良い根拠文」「悪い根拠文（節税訴求・数値捏造・社名露出）」のペアを `prompts/examples/` に置き、Step5 に2〜3例入れる。
- プロンプトはファイルで版管理し、`Case` に使用プロンプト版を記録する。

## 14. 非機能要件
- **性能**：§1.3。Step5 は3案を並列生成可能にする（1回の呼び出しと並列の両方を実装し、Phase 4で比較）
- **可用性**：LLM呼び出しは指数バックオフで2回リトライ、タイムアウト45秒。失敗時は計算結果（数値・3案構成）だけで定型文テンプレートの資料を出せる**フォールバック**を用意
- **セキュリティ**：商談ログ・企業情報は機微情報。保存時暗号化（本番DB）、アクセスはロールと所有者で制御、共有リンクは有効期限付き、監査ログ（誰が・いつ・何を生成/出力/承認したか）。LLMに送る前に個人名・電話番号・メールアドレスをマスキングできる設定を用意
- **データ保持**：案件データの保持期間を設定可能（既定1年）、削除機能
- **ログ**：プロンプト版・ナレッジ版・モデル名・トークン数・所要時間を Case ごとに記録
- **アクセシビリティ**：タップ領域44px以上、コントラストAA

## 15. やってはいけないこと
- LLMに保障額・保険料・税額を計算させること、LLMの出力した数値をそのまま資料に載せること
- 顧客提示物に保険会社名・商品名・ファンド名・資料番号を出すこと（営業メモでも既定は非表示）
- 「節税」を目的や効果として訴求すること、保証・断定・他社比較の表現
- 出典・基準日のない数値や統計を根拠文に使うこと
- 参考資料の文章・図表をそのまま資料に転載すること（要点を自分の言葉で要約し、出典を示す）
- 仮置き値を確定値のように表示すること
